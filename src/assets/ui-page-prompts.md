# 宝宝健康档案缺失页面与 UI 提示词

本文档基于当前 `README.md`、现有 4 个 tab 设计稿，以及当前项目已落地的业务范围整理。

目标：

- 列出每个 tab 下仍缺失的页面
- 给出每个页面可直接继续生成设计稿的 UI 提示词
- 保持整套小程序视觉统一

统一视觉约束：

- 风格：亲子温馨、可信赖、轻医疗感，不做冷冰冰医院风
- 气质：真实产品感，不要明显 AI 感，不要过度梦幻插画
- 色彩：以暖白、米色、浅杏色、淡橙、浅青绿、浅蓝为主
- 渐变：少用，只在局部氛围或按钮高光轻微使用，避免大面积强渐变
- 组件：卡片化、圆角、轻阴影、留白充足
- 字体层级：清晰克制，不做夸张大标题堆叠
- 图标：简洁、统一线性或轻拟物风格
- 页面结构：优先真实小程序信息架构，避免“概念海报感”
- 底部 tabbar：与现有首页、健康页、提醒页、我的页保持一致，固定为“首页 / 健康 / 提醒 / 我的”
- tabbar 当前页高亮：详情页虽然是二级页，但设计稿中底部 tabbar 仍需高亮其所属模块，对应图标与文案高亮，其他 tab 保持未选中状态

## 首页 Tab 缺失页面

### 1. 病历列表页

用途：

- 承接首页“最近记录 -> 查看全部”
- 展示当前宝宝全部病历和健康记录

UI 提示词：

```text
为“宝宝健康档案”小程序设计一张病历列表页 UI。页面属于首页下钻页，延续现有温暖亲子风格，低 AI 感，少用渐变，整体像真实可上线的小程序。页面顶部显示当前宝宝信息和切换入口，中间是病历筛选区，支持按时间、症状、记录类型筛选，主体为病历列表卡片。每条记录展示日期、医院、症状标签、记录类型、简短摘要，并有“查看详情”入口。底部延续统一 tabbar 风格，但当前页面是二级页，不强调 tab 切换。配色以暖白、米色、浅橙、浅青绿为主，卡片圆角、轻阴影、留白充足，避免过度插画和强渐变。
```

### 2. 病历详情页

用途：

- 承接首页、健康页中单条病历点击后的详情查看

UI 提示词：

```text
为“宝宝健康档案”小程序设计一张病历详情页 UI。页面风格与现有首页、健康页一致，亲子温暖、真实产品感、低 AI 感、少渐变。页面展示当前宝宝名称、就诊日期、医院、科室、主诉、诊断、处理建议、用药信息、备注等完整病历内容。结构要清晰，采用分组卡片展示，支持附件占位区和“再次记录”“复制为新记录”这类次级操作入口。视觉以暖白底、浅灰分隔、淡橙和浅青绿点缀，避免大面积夸张插画，更像真实医疗记录详情页。
```

为“宝宝健康档案”小程序设计一张“新增生病记录”页面 UI。页面需要延续现有小程序整体风格：温暖亲子、克制、低 AI 感、少渐变。页面是表单页，包含当前宝宝信息、症状输入、开始时间、体温、精神状态、饮食睡眠、护理措施、备注等字段。可加入热门症状快捷标签，如发热、咳嗽、湿疹、腹泻。底部有主操作按钮“保存记录”。视觉上用浅色卡片分组表单，减少装饰，突出可填写性和真实产品感。
